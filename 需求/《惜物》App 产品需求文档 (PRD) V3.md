# **个人资产管理 App《惜物》产品需求文档 (PRD)**

## **1\. 产品概述**

**产品名称：** 惜物 (Xī Wù)  
**产品理念：** 万物皆有成本，认清真实消费。珍惜物品，物尽其用。  
**一句话简介：** 一款帮你追踪个人消费品折旧情况，计算物品“日均使用成本”的实用主义生活手账风管理工具。  
**目标用户：** 关注个人财务状况的人群、极简主义者、看重“实用主义”和“理性消费”的年轻人。

## **2\. 核心功能需求 (MVP 阶段 V1.0)**

### **2.1 资产录入与管理**

* **添加资产：** 必填项包括资产名称、买入价格、买入日期、当前残值（二手估价）。  
* **物品分类细化：**  
  * 📱 数码外设（手机、电脑、相机）  
  * 🚗 交通出行（汽车、自行车、摩托车）  
  * 🛋️ 大件家居（冰箱、洗衣机、人体工学椅）  
  * 👜 服饰箱包（名表、奢侈品包）  
  * 🎫 权益/服务（健身卡、视频会员）  
* **物品生命周期管理：** 分为“服役中”（正常每天计算更新使用成本）和“已出掉/转卖”（记录最终真实售出价格，锁定历史日均使用成本）。

### **2.2 核心数据与计算逻辑 (看板模块)**

* **总资产概览：** 顶部展示当前总资产残值、总投入本金及总损耗。  
* **单项资产详情页：** 展示买入时长（已持有天数）。  
* **核心算法：** (当前残值 \- 买入价格) ÷ 持有天数 \= 日均使用成本（负数代表每天的使用成本，正数代表赚取的收益）。

### **2.3 简易折旧公式 (自动化核心)**

提供预设折旧模型，App 每天自动帮用户扣减残值：

| 模型名称 | 计算逻辑 | 适用场景 |
| :---- | :---- | :---- |
| 模型 A：直线归零法 | 设定“预期使用寿命”，价值每天平均递减，直至为 0。 | 权益、消耗品（如年卡、跑鞋） |
| 模型 B：落地打折 \+ 持续贬值 | 购买拆封瞬间扣除 X% 价值，之后每年再按 Y% 贬值。 | 硬核消费品（如数码产品、汽车） |
| 模型 C：保值/缓慢折旧法 | 设定保底的“残值底线”，前期缓慢折旧，跌至保底价后不再下跌。 | 奢侈品、贵金属、高端家具 |

### **2.4 基础账户与本地存储**

* **数据存储：** 第一版做纯本地数据存储，保护隐私且开发快捷。  
* **数据导出：** 支持用户将数据导出为 Excel (CSV) 格式，防止丢失。

## **3\. 视觉与体验设计 (UI/UX)**

* **整体风格：** 轻松活泼的生活手账风，降低算账的心理负担。  
* **色彩与形状：** 采用温暖明快的颜色（马卡龙色系/莫兰迪色系），大量使用大圆角卡片设计。  
* **Emoji 视觉化：** 物品分类和详情页大量使用 Emoji 代替严肃的传统分类图标。  
* **趣味文案：** 采用拟人化、有人情味的提示语（如：“相当于省下了一口奶茶！”）。

## **4\. 未来迭代需求 (Phase 2 & V1.5)**

* **AI 估价助手 (V1.5核心)：** 详情页增加“魔法棒”按钮，对接 AI 大模型 API。根据物品名称、买入时间、新旧程度，一键获取预估二手价格区间并同步更新当前残值。  
* **差异化“情绪价值”功能：**  
  * **星巴克/奶茶换算器：** 将日均成本具象化直观对比增强用户感知。  
  * **回本里程碑：** 高价物品日均成本降至特定值（如 1元/天以下）时，触发“已回本/超值”的贴纸/盖章动画特效。  
* **云端同步：** 引入账号注册系统（手机号、微信、Apple ID等），实现多端多设备数据同步。  
* **图表分析与多币种：** 饼图展示资产配置比例，折线图展示总值走势，以及支持不同国家货币的汇率折算。

## **5\. 技术栈规划 (已确认方案)**

* **前端跨平台框架：** Flutter (Dart语言)。追求极致UI表现，自带渲染引擎，能完美还原大圆角卡片和手账风动画效果。  
* **本地数据库 (MVP阶段)：** Isar 或 Hive (专为Flutter打造的轻量级NoSQL数据库，读写极速)。  
* **状态管理：** GetX (适合个人开发者快速上手，代码结构简洁)。  
* **后端微服务 (V1.5阶段)：** Python \+ FastAPI。用于构建 AI 估价接口服务，对接大模型API，充分发挥开发者的 Python 技能优势。

## **6\. 本地数据库设计 (Isar/Hive 核心表结构)**

针对 V1.0 MVP 需求，核心表为**物品表 (AssetItem)**，配合枚举类型管理状态和分类。

### **6.1 核心表：物品表 (AssetItem)**

| 字段名 (Field) | 数据类型 (Type) | 必填/选填 | 说明 / 用途 |
| :---- | :---- | :---- | :---- |
| id | Id (int) | 必填 | 数据库主键，自动递增。 |
| name | String | 必填 | 物品名称（例如：“iPhone 14 Pro”）。 |
| emojiIcon | String | 必填 | 物品的视觉图标，契合手账风（例如：“📱”）。 |
| category | Enum | 必填 | 物品分类（数码外设、交通出行、大件家居等）。 |
| buyPrice | double | 必填 | 买入时的价格。 |
| buyDate | DateTime | 必填 | 买入的日期，用于计算“已持有天数”。 |
| currentValue | double | 必填 | 当前残值。刚买时等于买入价，后续由折旧公式或手动更新。 |
| depreciationModel | Enum | 必填 | 选定的折旧公式（直线归零、落地打折、缓慢折旧）。 |
| status | Enum | 必填 | 生命周期状态（服役中、已出掉/转卖）。 |
| sellPrice | double | 选填 | 最终卖出/闲置时的实际价格。状态变为“已出掉”时填写。 |
| sellDate | DateTime | 选填 | 最终卖出/退役的日期。用于锁定最终的日均使用成本。 |
| note | String | 选填 | 用户的备注或碎碎念。 |

### **6.4 辅助枚举 (Enums)**

* **资产分类 (AssetCategory):** digital (数码外设), transport (交通出行), furniture (大件家居), fashion (服饰箱包), service (权益/服务)  
* **折旧模型 (DepreciationModel):** modelA\_Linear (直线归零法), modelB\_DropAndDecay (落地打折+持续贬值), modelC\_SlowDecay (保值/缓慢折旧)  
* **生命周期状态 (ItemStatus):** active (服役中), archived (已出掉)

### **6.5 设计说明**

**日均使用成本计算：**作为派生数据（Derived Data），不在数据库中直接存储。由于其随时间动态变化，采取的策略是每次打开 App 渲染界面时，利用公式 (currentValue \- buyPrice) / (当前日期 \- buyDate) 进行实时动态计算，以节省频繁更新的数据库读写性能消耗。
